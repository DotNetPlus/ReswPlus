    Make the Native AOT sample publishable on every architecture
    
    Three things stood between the sample and a deployable app.
    
    Building it for anything but x64 produced a project whose generated
    resource class did not exist, so the XAML compiler failed on every page
    that used it. The platform an app is built for is passed down to the
    projects it references, and the generator is a netstandard2.0 analyzer
    that has no platform: built as x86 or ARM64 it is an assembly Roslyn
    declines to load, and an analyzer that fails to load generates nothing.
    Every sample now pins that reference to AnyCPU. This was not specific to
    the new sample -- the existing ones were equally unbuildable for x86 and
    ARM64, and are fixed with it.
    
    Publishing produced an ordinary self-contained app rather than a native
    one: the AOT compiler is brought in by the restore, so asking for it only
    in the publish profile was asking too late, and the publish quietly fell
    back. It is declared in the project instead, together with the runtime
    identifiers it resolves against -- which is also what the earlier crash
    was really about. PublishAot without RuntimeIdentifiers is what produced
    an app that threw inside Windows.UI.Xaml before its first window, not
    Native AOT itself, so the correction is recorded where the wrong
    explanation was.
    
    Verified by publishing all three: win-x64, win-arm64 and win-x86 each
    produce a single native executable of a few megabytes with no assemblies
    beside it, and the resources compiled into it.
