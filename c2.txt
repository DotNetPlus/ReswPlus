    Make the Native AOT sample actually start
    
    The sample built, but it fail-fasted the moment it was run.
    
    Two things were wrong. It had no launch profile, so the IDE started the raw
    executable rather than the app: the crash record showed an empty faulting
    package name, and UWP XAML cannot start without package identity. And the
    Release configuration turned Native AOT on for an ordinary build, which
    produced an executable that threw inside Windows.UI.Xaml before its first
    window. Native AOT is applied when the app is published, so it now lives in
    the publish profiles, next to the runtime identifier it belongs with, and
    building and running the sample works in either configuration.
    
    Verified by packaging, installing and driving the Release x64 build: the app
    starts, every sample page is there, and the strings it renders are the
    generated ones -- including the pluralized resource picking its singular
    form for one and its plural form for ninety-nine.
    
    Also record how to build, launch and recover this sample in repo memory, and
    let the solution register the shared projects the way the IDE expects.
    
    Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>

+</Project>
